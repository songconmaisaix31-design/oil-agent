## Shared contract for AB and D

Import DTOs from `oil_agent.contracts.dto`, mobile envelopes from
`oil_agent.contracts.http`, and async protocols from `oil_agent.contracts.services`.
The module docstrings define side-effect, timeout, retry and ownership boundaries.

The sole generated mobile schema is `src/oil_agent/contracts/openapi.json` (14
paths), generated by `uv run python -m oil_agent.api.export_openapi`; its equality
with `create_app().openapi()` is tested. D must generate client types from this
artifact. Python DTOs and the FastAPI route declarations remain authoritative.

- `SourceAdapter.fetch(cursor: SourceCheckpoint | None, *, context: CallContext)
  -> FetchBatch`: candidate cursor only; C commits records and checkpoint together.
- `AssessmentService.assess(records: tuple[SourceRecord, ...], *, context)
  -> tuple[EventAssessment, ...]`: conservative candidates only. C owns durable
  matching, stable event IDs and revision allocation; AB must not infer novelty
  merely from an empty history input.
- `ReportService.build(cutoff: ReportBuildRequest, *, context) -> Report`:
  facts carry specific `EvidenceRef` objects. AB must verify their record revision,
  field and excerpt against the request snapshot; schema validation alone does
  not prove that text supports a generated claim.
- `NotificationChannel.send(intent: NotificationIntent, *, context) -> Delivery`:
  C preallocates `intent.delivery_id`; D returns and embeds the same identifier.
  One intent has one recipient and exact object revision authorization.
- `AckVerifier.verify(payload: AckPayload, *, context) -> VerifiedAck`: D verifies
  signature/identity, C separately verifies current business authorization/replay.

Context has an absolute aware deadline, a positive timeout no greater than 60
seconds and an attempt from 1 through 3. Implementations enforce the remaining
budget; the protocol itself is not a timeout runner. Classified safe errors are
defined by `ServiceError`/`ErrorCode`. Ambiguous sends return `UNKNOWN` and must
not become automatic retryable timeouts. `dry_run` cannot claim platform acceptance.

Times reject naive datetimes and normalize to UTC. Prices reject binary floats,
nonfinite/negative amounts and excessive precision, and serialize as strings.
Evidence groups use original publishers; multi-source status requires at least
two distinct groups. Fixture labels and datasets must agree. Cross-object data
existence, semantic evidence support and live authorization remain runtime duties.

API prefix: `/api/v1`. Routes cover events/detail/ack/feedback, reports/detail,
quote preview/import, config/status and session. The authenticated
`/records/{record_id}/revisions/{revision}` route resolves cited source versions.
`EventDetail.deliveries` must contain only the caller's authorized recipient rows.
The quote upload contract is bounded base64 JSON CSV/XLSX followed by a persisted
preview ID; no import processing is implemented in this dispatch.

Anonymous business requests return 401; viewer management access returns 403.
Unimplemented business/session mutations return 501 with `code=not_implemented`.
No real session provider is installed: all cookie values fail closed until runtime
integration. Test identities exist only through explicit dependency overrides.
Health and status responses identify this as foundation and do not invent data.

## Storage and safety configuration

Alembic head: `0001_foundation`. Tables: `source_records`, `source_checkpoints`,
`business_config`, plus Alembic metadata. Source uniqueness and positive revisions
are enforced in PostgreSQL. The seeded singleton config has no recipient or
business scope, unset first-report policy, dry-run outbound mode and disabled
reminders/SMS/phone. The application refuses enabling these unimplemented sending
capabilities. No dotenv file is loaded automatically, and no startup migration or
background task runs implicitly.

`/healthz` proves process liveness; `/readyz` requires the exact migration head.
This foundation does not contain the events/outbox/ack/session runtime schema.
Source transaction tests exercise real SQLAlchemy/PostgreSQL rollback primitives;
they do not claim a completed ingestion or outbox pipeline.
