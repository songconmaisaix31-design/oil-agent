Export from `oil_agent.channels`:

```python
FeishuTenantLookup(
    settings: FeishuSettings,
    *,
    authorize_request: Callable[
        [Literal["tenant_token", "tenant_query"]], Awaitable[str]
    ],
    transport: httpx.AsyncBaseTransport | None = None,
)
async def lookup(*, context: CallContext) -> str: ...
```

Lookup requires enabled, explicit app ID/secret, but no preexisting tenant or
recipient. Its mandatory callback returns a nonempty durable reservation ID
before every HTTP operation, or raises to prevent that request. C binds that
callback to the exact app, host, immutable permission and common request ledger;
the same app/window budget must cover lookup **and later sends**, without a
second twenty-request allowance. Lookup creates no permission, recipient, delivery
claim, timestamp, private binding or send authority. C owns observation time,
later binding validation/storage and any runtime adapter.

The existing token implementation was extracted into `tenant_token.py`; both
`FeishuChannel` and `FeishuTenantLookup` use it with the existing `ProviderHTTP`.
Ordinary send/login `require_app()` and C1 send guards are unchanged. Cold lookup
uses a token POST then one tenant GET; a cached token uses only the GET. Token
expiry invalidates the cache for a subsequent explicitly initiated call, without
retrying. Returned data is only validated `data.tenant.tenant_key` (1-160 ASCII
identifier characters), never `display_id`, a configured fallback or raw body.
Failure exposes classified `ServiceError` with a fixed redacted message.

The fixed official routes are:

- `POST /open-apis/auth/v3/tenant_access_token/internal`, using only app ID/secret:
  [official token documentation](https://open.feishu.cn/document/ukTMukTMukTM/ukDNz4SO0MjL5QzM/auth-v3/auth/tenant_access_token_internal).
- `GET /open-apis/tenant/v2/tenant/query`, using the app's tenant token and requiring
  additional `tenant:tenant:readonly` permission:
  [official tenant documentation](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/tenant-v2/tenant/query).

Both use `https://open.feishu.cn`; there is no caller-supplied endpoint, automatic
retry, redirect, environment proxy, contact lookup, OAuth or message method.
`CallContext` bounds the complete operation, including authorization waits, and
the existing HTTP implementation bounds connect time/connections/response bytes.
Reservations can exceed completed HTTP calls if a deadline fails before the wire;
the returned key is not a usage receipt or proof of current phone authorization.
